# RE_048 · Few triangles per draw call

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | Medium | Playing | 30 FPS and 60 FPS |

## What it means

Your geometry is split into many small pieces. The frame is not expensive because of how much geometry
there is, but because of how many separate calls it takes to draw it — each small mesh pays the full
cost of a draw call for very little work.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| Triangles per mesh draw | Low | Average triangles drawn by each mesh draw call |
| Mesh draw calls | High | Draw calls that render geometry, not post-processing or UI |

A minimum number of draw calls keeps the rule quiet in a nearly empty scene, where the average is low
simply because there is little to draw.

## Why it happens

A draw call has a fixed cost on the CPU and in the driver, whether it draws ten triangles or ten
thousand. Small props placed one by one, modular kits cut into tiny pieces, and debris scattered as
individual actors all multiply that fixed cost without adding much geometry.

## How to fix it

1. **Instance the meshes that repeat.** Convert them to an Instanced Static Mesh or a Hierarchical ISM,
   so all copies go out in one call.
2. **Merge static geometry that is always seen together.** Use **Tools → Merge Actors** on props that
   never move independently.
3. **Use HLOD for what is far from the camera**, so distant clusters collapse into a single mesh.
4. **Check the draw call breakdown first.** If most calls are not geometry, the problem is elsewhere and
   merging meshes will not help.

## How to confirm the fix

Watch **Draw Calls** in Live Metrics. The number of mesh draw calls should drop while the triangle count
stays about the same — that is what a better split looks like.
