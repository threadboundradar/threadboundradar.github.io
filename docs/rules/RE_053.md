# RE_053 · Sustained editor memory growth

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Memory | High | Always — playing, loading, compiling and idle | 30 FPS and 60 FPS |

## What it means

The editor's own process memory is climbing at a sustained rate. The absolute size isn't the finding — a large project can occupy tens of gigabytes without trouble — the slope is.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Editor process memory growth | High | Rate at which the editor's own process memory is increasing |

The Diagnostics row quotes the exact growth rate and the current process memory total measured when it fired.

## Why it happens

A steady climb like this usually means something is being duplicated or retained instead of released — most often a world that should have been unloaded, or content streamed in faster than it's streamed back out.

## How to fix it

1. **Check whether it drops when you stop PIE.** If it doesn't, something is holding references to the previous world.
2. **Review how the map is split.** Loading everything at once instead of by cell is the usual cause.
3. **World Partition with smaller cells spreads the same content out over time**, instead of loading it all at once.
4. **If the growth happens without loading anything, look for accumulation** in arrays or objects that never get collected.

## How to confirm the fix

The Memory section's growth reading returns to "steady" instead of a climbing rate, and the rule's row in Diagnostics is no longer marked active.
