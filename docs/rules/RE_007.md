# RE_007 · High texture memory usage

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Memory | Medium | Playing | 30 FPS and 60 FPS |

## What it means

Texture data alone is using a large amount of VRAM. That leaves less margin for streaming, and on hardware with limited VRAM the engine starts evicting textures more aggressively than it should.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Texture memory | High | VRAM currently committed to texture data |

## Why it happens

Uncompressed textures, or textures kept at a resolution higher than their on-screen size needs, are the usual cause. Streaming is designed to keep only what's visible resident, but it needs a comfortable margin below the hardware's VRAM to do that without thrashing.

## How to fix it

1. **Audit the heaviest textures** using the Content Browser's Size Map, and look for uncompressed formats or resolutions beyond what the texture needs on screen.
2. **Adjust the Texture Streaming Pool Size only if the target hardware justifies a larger pool** — raising it papers over the problem rather than fixing it.
3. **Use Virtual Texturing on large landscape or terrain textures**, which is exactly the case it's built for.

## How to confirm the fix

Watch the texture rows in the Memory section of Live Metrics. Once texture memory falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
