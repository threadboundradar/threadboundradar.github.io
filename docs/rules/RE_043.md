# RE_043 · High Volumetric Cloud cost

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | Medium | Playing | 30 FPS and 60 FPS |

## What it means

Volumetric cloud rendering is consuming a significant share of the frame. This is read live from the engine's own stat system, the same as RE_041.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Volumetric Cloud cost | High | GPU time spent rendering volumetric clouds |

## Why it happens

Volumetric clouds are raymarched, and the cost scales directly with how many samples that raymarching takes — a higher sample count for either the view or the shadow pass costs proportionally more GPU time.

## How to fix it

1. **Reduce the cloud raymarching quality** — View Sample Count and Shadow Sample Count on the component.
2. **Check whether the clouds are actually visible or needed** in every scene where they're active.
3. **Consider a reduced render resolution specific to the cloud pass**, if the project allows it.

## How to confirm the fix

Run `stat gpu` in the console and watch the **VolumetricCloud** row — it is the same stat the plugin reads. Once it falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
