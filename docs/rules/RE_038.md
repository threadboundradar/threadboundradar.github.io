# RE_038 · Tick cost concentrated in few classes

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Blueprint | Medium | Playing | 30 FPS and 60 FPS |

## What it means

The aggregate Blueprint tick cost is high, but it comes from three classes or fewer. Unlike RE_035 — many cheap classes — the problem here is concentrated and easier to isolate and fix.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| Blueprint tick class count | Low | Distinct Blueprint classes running Event Tick this frame |
| Blueprint total tick cost | High | Sum of Event Tick cost across all Blueprint classes this frame |

## Why it happens

When a significant tick cost comes from very few classes, each one is individually expensive — this is a better return on effort than a broad tick audit, because fixing a handful of classes accounts for nearly all of the cost.

## How to fix it

1. **Review the flagged classes directly in the Gameplay Profiler panel** — there are few of them, so diagnosis should be quick.
2. **Prioritize these classes over a general tick optimization pass**, since the return on fixing them is high.

## How to confirm the fix

Watch the Blueprint tables in the Gameplay Profiler panel for the classes you changed. Once the combined tick cost falls back under the rule's threshold, or the number of ticking classes rises past the rule's limit, the rule stops firing and its row in Diagnostics is no longer marked active.
