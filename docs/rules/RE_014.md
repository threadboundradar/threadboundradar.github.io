# RE_014 · CPU and GPU saturated simultaneously

| Category | Severity | Fires while | Target |
|---|---|---|---|
| General | High | Playing | 30 FPS and 60 FPS |

## What it means

Both the game thread and the GPU are over budget at the same time. There is no single bottleneck here — optimizing only one side won't move the frame rate by much.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| Game thread time | High | Time the main game thread spends this frame |
| GPU time | High | Time the GPU spends on this frame |

## Why it happens

When both sides are over budget, the frame time is set by whichever is worse, so trimming the other one first buys nothing until it catches up. This pattern is also a sign that some work might be duplicated between gameplay and rendering — the same calculation done twice, once on each side.

## How to fix it

1. **Prioritize whichever of the two — CPU or GPU — is further from its own budget**, since that's the one currently setting the frame time.
2. **Check for duplicated work between gameplay and rendering**, such as visibility calculations done independently on both sides.

## How to confirm the fix

Watch **Game Thread** and **GPU Time** in Live Metrics. Once at least one falls back under its budget, the rule stops firing and its row in Diagnostics is no longer marked active.
