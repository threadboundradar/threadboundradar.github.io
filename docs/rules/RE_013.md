# RE_013 · Dense geometry impacting the GPU without excess draw calls

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | Medium | Playing | 30 FPS and 60 FPS |

## What it means

The GPU cost is coming from how detailed the geometry is, not from how many separate objects are being drawn. A relatively small number of draw calls is carrying a lot of triangles each.

## When it fires

All of these are true at the same time:

| Measurement | Looks for | What it is |
|---|---|---|
| GPU time | High | Time the GPU spends on this frame |
| Triangles drawn | High | Triangles submitted this frame, counted once per rendering pass |
| Draw calls | Low | Commands sent to the GPU this frame |
| GPU bound | Yes | The GPU, not the game thread, is what limits the frame |

## Why it happens

A handful of very high-poly meshes — a hero asset, an unoptimized import — can carry millions of triangles through only a few draw calls. Instancing doesn't help here, because the problem isn't repetition; it's the density of the individual mesh.

## How to fix it

1. **Enable Nanite on the highest-density meshes.**
2. **Set up more aggressive LODs** to cut triangle count at distance.
3. **Check whether the heaviest individual mesh justifies its level of detail** in the context it's actually seen in.

## How to confirm the fix

Watch **GPU Time** and **Triangles** in Live Metrics. Once GPU time falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
