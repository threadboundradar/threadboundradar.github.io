# RE_021 · Excess draw calls with render thread critical (not GPU-bound, 30 FPS)

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | High | Playing | 30 FPS and 60 FPS |

## What it means

The same submission-overhead pattern as RE_020, at a level that already compromises even a 30 FPS target.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| Draw calls | High | Commands sent to the GPU this frame |
| Render thread time | High | Time the render thread spends building the frame for the GPU |
| GPU bound | No | The GPU is not what limits the frame |

## Why it happens

Each draw call carries a fixed CPU cost to build and submit, independent of the GPU's own cost to execute it. At this severity, that submission overhead is costing enough on its own to break a 30 FPS budget.

## How to fix it

1. **Prioritize reducing draw calls via instancing** over any GPU-side optimization — it won't help this pattern.
2. **Check whether the RHI Thread is enabled and balancing the load correctly.**
3. **Profile the command submission phase with Unreal Insights.**

## How to confirm the fix

Watch **Draw Calls** and **Render Thread** in Live Metrics. Once draw calls fall back under the rule's threshold or the render thread returns under its budget, the rule stops firing and its row in Diagnostics is no longer marked active.
