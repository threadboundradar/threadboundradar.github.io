# RE_011 · Frame outside the 60 FPS budget

| Category | Severity | Fires while | Target |
|---|---|---|---|
| General | Low | Playing | 60 FPS only |

## What it means

The whole frame took longer than 60 FPS allows. This rule doesn't diagnose why by itself — it's a general trip-wire so a slow frame gets flagged even when no more specific rule matches.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Frame time | High | Total time to produce this frame |

This rule only applies to a 60 FPS target. The plugin hides it entirely when the project's target frame rate is set to 30 FPS, where the same measurement can still fit the budget.

## Why it happens

A frame can miss budget for many different reasons — this rule only confirms that it happened. The real diagnosis comes from whichever more specific rule fired in the same second.

## How to fix it

1. **Check the Diagnostics table for other rules active in the same second** — that tells you whether the cause is on the CPU, GPU or memory side.
2. **Confirm the target frame rate configured in the panel matches your project's actual target** — a mismatched target makes this rule fire, or stay quiet, for the wrong reason.

## How to confirm the fix

Watch **Frame Time** in Live Metrics. Once it falls back under the 60 FPS frame budget, the rule stops firing and its row in Diagnostics is no longer marked active.
