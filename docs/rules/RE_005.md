# RE_005 · Sustained GPU-bound (60 FPS)

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | Medium | Playing | 60 FPS only |

## What it means

The frame is missing its 60 FPS budget, and the GPU — not the CPU — is why. This rule alone doesn't say what on the GPU is expensive; it confirms where to look next.

## When it fires

All of these are true at the same time:

| Measurement | Looks for | What it is |
|---|---|---|
| GPU time | High | Time the GPU spends on this frame |
| GPU bound | Yes | The GPU, not the game thread, is what limits the frame |
| Frame time | High | Total time to produce this frame |

This rule only applies to a 60 FPS target. The plugin hides it entirely when the project's target frame rate is set to 30 FPS, where the same measurement can still fit the budget.

## Why it happens

GPU-bound means the GPU, not the CPU, is what sets the frame time. Whichever pass — geometry, shading, post-process, texture sampling — is eating the budget, the fix has to reduce work the GPU does, not the CPU.

## How to fix it

1. **Reduce render resolution or enable TSR upscaling.**
2. **Check which more specific rendering rule is active in the same second** — draw calls, triangle count or shading cost — to find the actual cause.
3. **Profile the costliest rendering phase with Unreal Insights** (GBuffer, Shadows, Post Process).

## How to confirm the fix

Watch **GPU Time** and **Frame Time** in Live Metrics. Once GPU time falls back under the rule's limit, the rule stops firing and its row in Diagnostics is no longer marked active.
