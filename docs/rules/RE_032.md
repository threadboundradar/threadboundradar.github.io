# RE_032 · Game thread near the limit with GPU idle

| Category | Severity | Fires while | Target |
|---|---|---|---|
| CPU | Medium | Playing | 30 FPS and 60 FPS |

## What it means

The game thread is close to saturating while the GPU is clearly idle. This imbalance suggests an opportunity to move work from CPU to GPU, or to better parallelize the game thread's own work.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| Game thread time | High | Time the main game thread spends this frame |
| GPU time | Low | Time the GPU spends on this frame |
| GPU bound | No | The GPU is not what limits the frame |

## Why it happens

A GPU sitting mostly idle while the CPU struggles is spare compute capacity going unused. Some gameplay calculations — simulations, batch queries — can run on the GPU as compute work instead, and CPU-bound frames often have game thread work that isn't parallelized across the Task Graph as well as it could be.

## How to fix it

1. **Evaluate whether any heavy gameplay logic is a candidate for a compute shader.**
2. **Review Task Graph usage and parallelization of the game thread's costliest work.**

## How to confirm the fix

Watch **Game Thread** relative to **GPU Time** in Live Metrics. Once the game thread falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
