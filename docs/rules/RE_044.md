# RE_044 · High Niagara GPU cost

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | Medium | Playing | 30 FPS and 60 FPS |

## What it means

The combined GPU cost of Niagara systems — simulation, sorting, ribbons and related sub-passes — is high. This is read live from the engine's own stat system, the same as RE_041, and unlike RE_015's generic fill-rate signal, it points straight at Niagara.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Niagara GPU cost | High | Combined GPU time spent on Niagara simulation and rendering |

## Why it happens

GPU-simulated particle systems scale their cost with particle count and with how much per-particle work each system does — sorting for correct translucency ordering and ribbon generation are both comparatively expensive parts of that pipeline.

## How to fix it

1. **Review how many Niagara systems are active simultaneously**, and whether they can be grouped or pooled.
2. **Lower the spawn rate or maximum particle count of the heaviest emitters.**
3. **If the simulation doesn't need to run on GPU, consider moving the emitter to CPU** — fewer particles, but without this GPU cost.

## How to confirm the fix

Run `stat gpu` in the console and add up the rows whose name contains **Niagara** — the plugin sums the same stats. Once the total falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
