# RE_026 · Elevated game thread — early warning (60 FPS)

| Category | Severity | Fires while | Target |
|---|---|---|---|
| CPU | Low | Playing | 60 FPS only |

## What it means

The game thread already consumes most of the 60 FPS budget, without the GPU being the bottleneck. This is an early signal before reaching the threshold in RE_009.

## When it fires

All of these are true at the same time:

| Measurement | Looks for | What it is |
|---|---|---|
| Game thread time | High | Time the main game thread spends this frame |
| GPU bound | No | The GPU is not what limits the frame |

This rule only applies to a 60 FPS target. The plugin hides it entirely when the project's target frame rate is set to 30 FPS, where the same measurement can still fit the budget.

## Why it happens

Gameplay systems tend to grow their per-frame cost gradually as content is added — more actors ticking, more physics queries, more Blueprint logic — until they cross the point where the game thread is the limit.

## How to fix it

1. **Review which gameplay systems grew recently**, before this becomes a frame rate problem.
2. **Consider profiling preventively with `stat game`.**

## How to confirm the fix

Watch **Game Thread** in Live Metrics. Once it falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
