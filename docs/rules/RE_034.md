# RE_034 · Critical Blueprint tick

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Blueprint | High | Playing | 30 FPS and 60 FPS |

## What it means

A single Blueprint class is consuming a very large amount of Event Tick time this frame — a cost larger than most of the rest of the game thread combined. This needs immediate attention.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Blueprint max tick cost | High | The single most expensive Blueprint class's Event Tick cost this frame |

## Why it happens

At this cost, the Event Tick graph is almost certainly doing something it shouldn't every frame: a loop over many objects, a chain of expensive casts, or a call into a heavy function that doesn't need to run at this frequency.

## How to fix it

1. **Open the Gameplay Profiler panel and review the flagged class's Event Tick graph as a priority.**
2. **Look for loops, costly casts, or calls to heavy functions inside the tick graph.**
3. **Consider disabling this class's tick and replacing it with targeted events**, if possible.

## How to confirm the fix

Watch the Blueprint tables in the Gameplay Profiler panel. Once the class's tick cost falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
