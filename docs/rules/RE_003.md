# RE_003 · High shading cost with few draw calls (60 FPS)

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | Medium | Playing | 60 FPS only |

## What it means

The GPU is spending more than a 60 FPS frame's worth of time despite drawing relatively few objects. The cost is in what each draw call does, not in how many of them there are — expensive shaders or stacked translucency are the usual suspects.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| GPU time | High | Time the GPU spends on this frame |
| Draw calls | Low | Commands sent to the GPU this frame |
| GPU bound | Yes | The GPU, not the game thread, is what limits the frame |

This rule only applies to a 60 FPS target. The plugin hides it entirely when the project's target frame rate is set to 30 FPS, where the same measurement can still fit the budget.

## Why it happens

A draw call's shading cost depends on the material's instruction count and how many times each pixel gets shaded — once for an opaque surface, but once per overlapping layer for translucency. Complex material graphs with many texture samples and layered blends, or particle effects and foliage with stacked translucent passes, drive GPU time up without adding a single draw call.

## How to fix it

1. **Check the complexity of your most-used materials** in Material Stats or the Shader Complexity view.
2. **Look for overdraw in particle systems and vegetation** — translucent layers stacked on top of each other are the most common cause.
3. **Profile with Unreal Insights** to see exactly which rendering pass is consuming the time.

## How to confirm the fix

Watch **GPU Time** in Live Metrics. Once it returns under the 60 FPS frame budget, the rule stops firing and its row in Diagnostics is no longer marked active.
