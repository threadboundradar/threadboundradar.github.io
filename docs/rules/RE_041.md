# RE_041 · High TSR cost

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Rendering | Medium | Playing | 30 FPS and 60 FPS |

## What it means

The temporal upscaling pass (TSR) is consuming a significant share of the frame. This measurement is read live from the engine's own stat system — the same one behind the `stat gpu` console command — so it points straight at TSR rather than post-processing in general.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| TSR cost | High | GPU time spent in the Temporal Super Resolution upscaling pass |

## Why it happens

TSR's cost scales with the resolution it's upscaling from and with how much history and reprojection work it's configured to do — a higher input resolution or a more aggressive history setting both raise this cost directly.

## How to fix it

1. **Reduce the render resolution feeding TSR** via the `r.ScreenPercentage` console variable.
2. **If TSR isn't essential for the project, try a different anti-aliasing method** via `r.AntiAliasingMethod`.
3. **Review `r.TSR.History.ScreenPercentage` and `r.TSR.ReprojectionField`** — more aggressive history settings cost more GPU time.

## How to confirm the fix

Run `stat gpu` in the console and watch the **TemporalSuperResolution** row — it is the same stat the plugin reads. Once it falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
