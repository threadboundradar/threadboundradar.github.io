# RE_040 · CPU and GPU both elevated without exceeding budget yet

| Category | Severity | Fires while | Target |
|---|---|---|---|
| General | Medium | Playing | 60 FPS only |

## What it means

The early version of RE_014: both the game thread and the GPU are already close to their own budgets, though the whole frame still meets 60 FPS. With no single bottleneck to attack, the margin for adding more content is limited.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| Game thread time | High | Time the main game thread spends this frame |
| GPU time | High | Time the GPU spends on this frame |
| Frame time | Low | Total time to produce this frame |

This rule only applies to a 60 FPS target. The plugin hides it entirely when the project's target frame rate is set to 30 FPS, where the same measurement can still fit the budget.

## Why it happens

When both sides are already near their share of the budget, there's no slack left on either one — the next addition to the scene, whatever side it lands on, is likely to push the frame over budget.

## How to fix it

1. **Treat the remaining margin as scarce** when planning more content for this scene.
2. **Prioritize optimizations that benefit both CPU and GPU** — such as reducing duplicated work — over single-side improvements.

## How to confirm the fix

Watch **Game Thread** and **GPU Time** in Live Metrics. Once either falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
