# RE_016 · Elevated texture memory — early warning

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Memory | Low | Playing | 30 FPS and 60 FPS |

## What it means

Texture data is already using a notable amount of VRAM. It's not critical yet, but the trend is worth watching before it grows further.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Texture memory | High | VRAM currently committed to texture data |

## Why it happens

This is the same cause as RE_007 and RE_008, just earlier: textures kept at a resolution or format heavier than their on-screen use requires, adding up across the project.

## How to fix it

1. **Check which texture categories are growing fastest** using the Content Browser's Size Map.
2. **Confirm new textures use appropriate resolution and compression** for how they're actually seen on screen.

## How to confirm the fix

Watch the texture rows in the Memory section of Live Metrics. Once texture memory falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
