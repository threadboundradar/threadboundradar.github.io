# RE_052 · System memory near the limit (percentage)

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Memory | Medium | Always — playing, loading, compiling and idle | 30 FPS and 60 FPS |

## What it means

Free system memory, measured as a percentage of installed RAM, has dropped very low. This is the same warning as RE_051, measured as a proportion instead of an absolute amount — which is what catches machines with little RAM to begin with: there, the amount left can still look like a comfortable margin while the share of memory left is already tight.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Free system memory | Low | Physical RAM not in use by any process, as a percentage of installed RAM |

The Diagnostics row quotes the exact free percentage, and the free and total memory in MB, measured when it fired.

## Why it happens

On a machine with less total RAM, an amount of free memory that wouldn't cross RE_051's absolute threshold on a larger machine can still mean the machine is already tight, since that same amount represents a much bigger share of its total memory. Measuring the proportion instead of the absolute amount catches that case.

## How to fix it

1. **Close applications not needed during the session** — browsers and chat clients are the usual suspects.
2. **Check whether there are multiple editor instances or background compiles running.**
3. **On machines with less total RAM, lower the texture streaming quality** to reduce the peak.

## How to confirm the fix

The Memory section shows free memory back above the rule's threshold percentage, and the rule's row in Diagnostics is no longer marked active.
