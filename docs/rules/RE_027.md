# RE_027 · Frame dominated by game thread with render thread low

| Category | Severity | Fires while | Target |
|---|---|---|---|
| CPU | Medium | Playing | 60 FPS only |

## What it means

The game thread exceeds budget while the render thread is clearly idle. Unlike RE_009, which only requires that the GPU not be the bottleneck, this rule rules out any rendering-side component entirely.

## When it fires

All of these are true at the same time, averaged over one second:

| Measurement | Looks for | What it is |
|---|---|---|
| Game thread time | High | Time the main game thread spends this frame |
| Render thread time | Low | Time the render thread spends building the frame for the GPU |

This rule only applies to a 60 FPS target. The plugin hides it entirely when the project's target frame rate is set to 30 FPS, where the same measurement can still fit the budget.

## Why it happens

An idle render thread means the frame's rendering work is trivial — whatever is costing the time is gameplay logic, physics, or Blueprints on the main thread, with nothing rendering-related to blame.

## How to fix it

1. **Profile with Unreal Insights, focusing exclusively on the game thread.**
2. **Review physics, AI, or Blueprint systems** — the idle render thread confirms this isn't a rendering problem.

## How to confirm the fix

Watch **Game Thread** relative to **Render Thread** in Live Metrics. Once the game thread falls back under the 60 FPS frame budget, the rule stops firing and its row in Diagnostics is no longer marked active.
