# RE_035 · Many Blueprint classes ticking simultaneously

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Blueprint | Medium | Playing | 30 FPS and 60 FPS |

## What it means

Many distinct Blueprint classes run Event Tick in the same frame. Even if none is individually costly, the per-class overhead of calling into each one adds up.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Blueprint tick class count | High | Distinct Blueprint classes running Event Tick this frame |

## Why it happens

Every ticking Blueprint class pays a fixed call overhead (ProcessEvent) even when its own logic is trivial. Enough of these calls every frame is measurable even with no single expensive class to blame.

## How to fix it

1. **Review which of these classes actually need to tick every frame** versus an event or a Timer.
2. **Evaluate a centralized or manual tick system** for actors that don't need native tick granularity.

## How to confirm the fix

Watch the Blueprint tables in the Gameplay Profiler panel: fewer classes should appear there once you move logic off Tick. Once the number of ticking classes falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
