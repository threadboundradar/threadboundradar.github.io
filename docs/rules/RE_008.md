# RE_008 · Critical texture memory usage

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Memory | High | Playing | 30 FPS and 60 FPS |

## What it means

Texture data alone is using a very large amount of VRAM — a level that compromises stability on most mid-range desktop hardware, not just consoles or mobile.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Texture memory | High | VRAM currently committed to texture data |

## Why it happens

This is the same over-provisioning problem as RE_007 taken further: textures kept larger or less compressed than their on-screen use requires, multiplied across enough assets to threaten the VRAM budget of your target hardware directly.

## How to fix it

1. **Audit the heaviest textures in the project** using the Content Browser's Size Map.
2. **Review mip maps and compression formats per texture type** (albedo, normal, masks) — each has a compression setting suited to it, and many projects default to one setting for all of them.
3. **Use Virtual Texturing on large landscape or terrain textures.**

## How to confirm the fix

Watch the texture rows in the Memory section of Live Metrics. Once texture memory falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
