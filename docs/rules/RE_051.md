# RE_051 · System RAM almost exhausted

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Memory | High | Always — playing, loading, compiling and idle | 30 FPS and 60 FPS |

## What it means

Free system memory has dropped very low. Below that margin Windows starts moving memory to disk, and
the machine stops being limited by the CPU or GPU: it is limited by disk access. The result is stutters
that no other number in the panel explains.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Free system memory | Low | Physical RAM not in use by any process |

The Diagnostics row quotes the free and total memory measured when it fired.

## Why it happens

The editor is rarely the only thing using memory, but it is usually the largest. A Play-in-Editor
session keeps two copies of the world alive — the editor's map and the one being played — so memory
jumps when you press Play, and again when a large map loads on top of that.

## How to fix it

1. **Open the Memory section of the panel** to see what is growing: it separates the editor's memory from
   the rest of the system.
2. **Remember that Play-in-Editor duplicates the world.** If memory runs out right after pressing Play,
   that duplicate is the likely cause.
3. **Restart the editor between long iterations** to release the copy of the world that stays in memory.
4. **Add RAM if the machine has free slots.** Everything else here reduces the problem; more memory
   removes it.

## How to confirm the fix

The Memory section shows free memory back above the rule's threshold and the rule's row in Diagnostics is no longer marked
active.
