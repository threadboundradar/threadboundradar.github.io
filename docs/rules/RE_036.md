# RE_036 · High aggregate Blueprint tick cost

| Category | Severity | Fires while | Target |
|---|---|---|---|
| Blueprint | Medium | Playing | 30 FPS and 60 FPS |

## What it means

The sum of Event Tick cost across all Blueprint classes this frame is high enough to matter for a 60 FPS target, attributable to Blueprint tick logic alone, whether it's concentrated in one class or spread across several.

## When it fires

| Measurement | Looks for | What it is |
|---|---|---|
| Blueprint total tick cost | High | Sum of Event Tick cost across all Blueprint classes this frame |

## Why it happens

This rule adds up every Blueprint class's tick cost, so it catches both a single heavy class and a crowd of moderately costly ones — either pattern can add up to the same total share of the frame.

## How to fix it

1. **Check the Gameplay Profiler panel to see whether the cost is concentrated** (see RE_038) **or spread across many classes** (see RE_035).
2. **Prioritize moving the tick logic with the highest accumulated cost to C++.**

## How to confirm the fix

Watch the Blueprint tables in the Gameplay Profiler panel for the classes you changed. Once the combined tick cost falls back under the rule's threshold, the rule stops firing and its row in Diagnostics is no longer marked active.
